  <files>src/components/ui/file-input.tsx, src/components/ui/file-input.module.css, src/app/styleguide/sections/file-input-section.tsx, test/app/file-input.spec.ts</files>
  <read_first>RESEARCH.md "Architectural Responsibility Map" (Browser/Client tier for anything needing `FileReader`/object URLs)</read_first>
  <behavior>
    - Choosing a file shows an `<img>` preview sized to a fixed box before any upload happens.
    - Choosing a second file replaces the preview and revokes the first file's object URL (`URL.revokeObjectURL`) — no leaked blob URLs across repeated selections.
    - With no file chosen, a placeholder (avatar-style or "No photo chosen" text) is shown instead of a broken image.
  </behavior>
  <action>
Build `ui/file-input.tsx`: `'use client' // client: needs FileReader/object-URL state for a preview before upload (R1)`. Props: `{ label: string; name: string; accept?: string } & Omit<ComponentPropsWithoutRef<'input'>, 'type'>`. `useState` for the preview URL; an `onChange` handler reading `event.target.files?.[0]`, calling `URL.createObjectURL(file)`, revoking the previous URL first if one exists; a `useEffect` cleanup revoking the current URL on unmount. Render the preview via `next/image` is not appropriate for a client-generated blob URL (next/image needs a known loader) — use a plain `<img>` here deliberately (documented exception; `next/image`'s U7 rule applies to served photos, not an ephemeral local preview) sized via `file-input.module.css` tokens, with `width`/`height` attributes to avoid layout shift. `file-input.module.css`: `@layer components`, placeholder state styled distinctly from the filled preview state.
  </action>

  </verify>

  <read_first>RESEARCH.md "Architecture Patterns → Pattern 4: Accessible star rating" (the full APG markup example and keyboard-interaction spec) and "Don't Hand-Roll" table (no role="slider", no hand-rolled arrow-key math)</read_first>
  <behavior>
    - `StarRating` (display) renders five peak/star glyphs reflecting a numeric `value` (supports halves, e.g. 4.5) with a single `aria-label="Rated 4.5 out of 5"` on the group — no `radiogroup`/`radio` roles, since it is not operable.
    - `StarRatingInput` renders a `<fieldset><legend>` wrapping a `role="radiogroup"` of five native `<input type="radio" name="rating">` elements, one per whole-star value 1–5, each paired with a `<label>` reading "{n} star" / "{n} stars". Tab moves focus into the group (landing on the checked button, or the first if none checked); Arrow keys move focus and selection between options; Space checks the focused option — all of this is native radio-input behaviour, with zero custom `keydown` handling written.
    - Selecting a star fires the input's native `onChange`, which the caller (a future Server Action wrapper, Phase 6) reads via `FormData` — this component holds no rating state itself beyond what the radios natively hold (uncontrolled, per the "pure/prop-driven" `ui/` boundary, DEL-12).
  </behavior>
  <action>
Build `ui/star-rating.tsx` as a Server Component: props `{ value: number; max?: number }` (`max` defaults to 5), renders `max` peak glyphs with filled/half/empty states driven by `value`, wrapped in a single element carrying `aria-label={`Rated ${value} out of ${max}`}` and `role="img"` (a static graphic, not a live region). `star-rating.module.css`: `@layer components`, uses `--color-accent` for filled peaks, never colour alone to carry meaning at a glance when used alongside the numeric label (the numeric label is always rendered as visible text next to the glyphs, matching direction.md's "★ 4.5" wireframe shape). Build `ui/star-rating-input.tsx`: `'use client' // client: a radiogroup of native radios needs no React state here, but the component exposes an onChange callback prop requiring a client boundary (R1)`. Props: `{ name: string; legend?: string; defaultValue?: number; onChange?: (value: number) => void }`. Render exactly the APG markup shape from RESEARCH.md Pattern 4: a `<fieldset>` with `<legend>{legend ?? 'Rate this tour'}</legend>`, a `<div role="radiogroup" aria-label="Rating">` containing five `<input type="radio" name={name} value={n} defaultChecked={defaultValue === n}>` + `<label>` pairs, each input's `onChange` calling the `onChange` prop with its numeric value — write no `onKeyDown` handler anywhere in this file (the native radios already implement the full APG keyboard spec). `star-rating-input.module.css`: visually hides the native radio circles and renders the five glyphs as the labels' `::before`/background content, keeping the inputs themselves present and focusable (never `display: none` on the inputs — that would remove them from the tab order), `:focus-visible` on the label associated with the focused input via the `:has()` selector or a sibling-selector equivalent, tokens only.
