## Decisions this plan locks in (binding for every later Phase 3 plan)

- **Testing strategy for interactive components (key constraint, resolved here):** no `jsdom`/`@testing-library/react` is added. Every interactive `ui/` component (mobile-menu, star-rating-input, confirm-dialog, file-input, toast) gets its behavioural test as a Playwright spec under `test/app/`, driving the real `/styleguide` route against a real `next dev` server — the styleguide's whole purpose (U5: every state, both themes, both widths) makes it the ideal fixture, and this avoids a new runtime/dev dependency the user already rejected a component-library equivalent of (RESEARCH.md "Alternatives Considered"). **Reversibility: reversible** — `@testing-library/react` can be added later with no rework of the components themselves, only of the tests.
- **`/styleguide`'s gating logic is a pure function, not inline in the page:** `src/app/styleguide/gate.ts` exports `loadStyleguidePage(appEnv: AppConfig['APP_ENV']): void`, which calls `notFound()` when `appEnv === 'production'`. The page component calls `loadStyleguidePage(getConfig().APP_ENV)` before rendering. This mirrors `test/examples/page-data.test.ts`'s `loadAccountPage`/`loadGuidePage` shape exactly, so the production-gate (S2) is unit-testable with `failureOf()`/`digestOf()` with no server, no module-cache reset, and no Playwright needed for this one check.
- **Styleguide sections are independent files, not one growing page body:** every later plan adds one `src/app/styleguide/sections/<name>-section.tsx` file (a Server or Client Component rendering that component's every state) and nothing else in `styleguide/`. Plan 03-10 (last wave) is the only plan that edits `src/app/styleguide/page.tsx` itself, importing every section — this keeps every component plan in Waves 2–3 conflict-free on this shared file. This plan creates the page with its own first section (`button-section.tsx`) directly, since there is nothing to conflict with yet.
</decisions>
