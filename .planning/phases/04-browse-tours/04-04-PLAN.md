## Phase Goal

ROADMAP Phase 4 goal, quoted verbatim (not in user-story form; no story is invented): A traveller can find a tour that fits their fitness, dates and budget, and see its route, itinerary, guides, reviews and photo credits. API clients get the same catalogue.

<objective>
The catalogue slice (D-11, D-12): one cached catalogue read and one pure query module serve both `/` and `GET /api/v1/tours`. `/` replaces the Phase 1 placeholder with the seeded tours in rating order, and the API offers allowlisted filters, `month`, `sort`, `fields` and pagination with `meta.total`. The cache design the roadmap asked this phase to settle (ARC-02, QA-12) is recorded in ADR 0031 and the contracts.

Purpose: a traveller sees real tours on the home page; API clients get the same data; plan 04-05 adds the filter form on top of this query module without touching the service.
Output: tours `service.ts`, `catalogue-query.ts`, `schemas.ts`, the list Route Handler, the new `/`, ADR 0031, the first OpenAPI fragment.
</objective>

<decisions>
- **Query contract (CONTEXT Claude's Discretion, named once).** Page `/`: `difficulty` (easy, medium, difficult), `length` (3-4, 5-6, 7-8), `month` (YYYY-MM, only a derived option), `maxPrice` (20000, 30000, 40000), `sort` (the API's own tokens: -ratingsAverage default, price, -price, duration, -duration), `page` (default 1, clamped), `limit` (1 to 100, default 12). API: filter fields `difficulty` (equality) and `price`, `duration`, `ratingsAverage`, `maxGroupSize` as equality or with `[gte]`, `[gt]`, `[lte]`, `[lt]`; `month`; `sort` (comma list, at most 5 tokens from price, ratingsAverage, duration, maxGroupSize, name, createdAt, each optionally prefixed `-`, default -createdAt per B1); `fields` (comma list of TourSummary keys; `id` always kept); `page`; `limit` (default 20). Every sort ends with name then id. Reversibility: costly — shared URLs and API clients depend on these names, but nothing is stored.
- **Month filter means an upcoming departure in that IST month**, on both `/` and the API, matching D-04's option list. Recorded in ADR 0031. Reversibility: reversible.
- **List shape follows plan.md 4.1**: `responses.list(key, items, meta)` nests items under `data[key]`. This returns to the spec's shape, so it needs no deviation ADR; contracts section 2.1 records it. Reversibility: costly (API clients read it), settled now before any client exists.
- **List row location is `startLocation.address`** ("Rishikesh, Uttarakhand"), per DES-02 and QA-02.
- **Component change C8**: `TourRow`'s `startDate` becomes optional and shows the approved line "No upcoming dates" when absent (DES-17, RESEARCH Pitfall 18).
</decisions>

- RESEARCH A2: an `unstable_cache` entry is limited to about 2 MB; 13 summaries are far below it. ADR 0031 says to revisit above roughly 500 tours.
- RESEARCH A8: `unstable_cache` with `revalidate: 3600` expires entries in `next dev` and `next start`; a reseed is seen after a restart or within an hour.
</assumptions>
