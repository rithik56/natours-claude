# Phase 04 — UI Design Contract

> Visual and interaction contract for Phase 4: Browse tours. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Three pages (`/` the tour list, `/tour/[slug]` the tour page, `/credits`) plus page metadata, `/sitemap.xml` and `/robots.txt`. The design direction ("Milestone", `docs/design/direction.md`) and the 27 finished `ui/` components are already approved. This contract describes how Phase 4's pages use them. It does not re-decide the design system.
>
> **Sources.** CONTEXT.md D-01 to D-12 are locked and used as written. Everything else is taken from `direction.md`, `copy.md`, the approved mockups and screenshots, `tokens.css`, the component source and the Phase 3 summaries. D-07 is used as amended on 2026-11-16 (the itinerary list stays visible beside the map; a static route holds the map slot until Leaflet loads). Anything the locked decisions leave open is marked **Proposed** and collected in "Open items" at the end; on 2026-11-16 the user adopted every Proposed item as the default, so the planner uses them as written (the planner may still refine items the CONTEXT leaves to its discretion, such as query parameter names). Every string not yet in `docs/design/copy.md` is listed in "New copy, needs approval".

### Changes to existing components (needed by this contract)

| # | Component | Change | Why |
|---|-----------|--------|-----|
| C1 | `booking-panel.module.css` and the `booking` variant in `skeleton.module.css` | Remove the pinned bottom bar below 64em. Below 64em the panel is a normal block in the page flow (`position: static`) with the same surface, hairline border on all sides and `radius-md` as at 64em. From 64em it stays sticky at `top: var(--space-5)` | D-06: "No pinned bottom bar." The skeleton must change in step with the panel (its own comment says so) |
| C2 | `tour-row.tsx` | Add optional `priority?: boolean`, passed to its `Image` | U7: `priority` only on the first visible photo. The first list row is the likely LCP image |
| C3 | `map-frame.tsx` and `map-frame.module.css` | Add `animate?: boolean` (default `true`). With `animate={false}` the route is drawn already complete (no draw animation: no `animation`, `stroke-dasharray: none`) | The slot's server-rendered content must not play the draw, because the Leaflet map plays it once when it scrolls into view (one self-playing motion, U25), and nothing may jump when Leaflet replaces it (D-07) |
| C4 | `map-frame.module.css` | Stop numerals `font-weight: 700` becomes `600` | The site declares exactly two weights (400 and 600). The Leaflet day markers use 600 as well |
| C5 | `src/lib/format.ts` | Add `formatMonth(value)` returning a month and year in IST, for example `Nov 2026` (three-letter month, year always shown, same convention as `formatDate`) | D-04. Only `formatPrice`, `formatDate` and `formatDistance` exist today |
| C6 | `map-frame.tsx` and `map-frame.module.css` | Bring the drawing geometry onto the token scale. Known limit of the finished component: it uses `PADDING = 28`, `MARKER_WIDTH = 22`, `MARKER_HEIGHT = 18`, `COLLISION_NUDGE = 14`, outline `stroke-width: 7` and marker `stroke-width: 2`, none of which is a multiple of 4 or a token. Change to `PADDING = 24` (the value of `--space-5`), `MARKER_WIDTH = 24` and `MARKER_HEIGHT = 20` (1.5rem by 1.25rem), `COLLISION_NUDGE = 12` (the value of `--space-3`), outline `stroke-width: 8`, route line stays `4`, and the marker's `stroke-width` becomes `var(--focus-ring-width)`. These are SVG user units inside the 400 by 240 `viewBox` (one unit equals one CSS pixel at the 400px drawing width and scales with the slot), and a Server Component cannot read a custom property, so the TypeScript constants carry the token values as numbers with a comment naming the token. A unit test reads `--space-3` and `--space-5` from `tokens.css` and fails if the constants drift | The Leaflet map (below) uses token-derived sizes and the static route must match it, so nothing changes size when Leaflet replaces it (D-07). The old numbers contradicted the "tokens only, multiples of 4" rule |
| C7 | `photo-credits.tsx` | Make `authorUrl` optional. When absent, the author renders as plain text (not a `Link`); the licence still links to `licenceUrl`. The list `key` must no longer be `authorUrl` (use `licenceUrl` plus the author name, or the index) | The seed's `photoCredits` entries have `author`, `license`, `licenseUrl`, `title` and `sourceUrl` but no author URL, so the component's required `authorUrl` cannot be filled with real data |

## Page contracts

### `/` Tour list

**Order (all widths):** `h1`, filter disclosure or form, result count, list (or empty state), pagination. The header and footer come from the shell. One `h1`.

**Primary visual anchor (focal point).** The `h1` "Find your next trip" at Display size (31.25px, weight 600, narrow, Neel on Whitewash) is the largest type on the page and the first thing read at every width. The eye then moves down to the first row's cover photo, the first image on the page (the `priority` image, C2). The filter panel is deliberately quieter: Paper surface, hairline border, no accent while closed. From 64em, and on a phone once the disclosure is open, the Highway yellow "Show tours" button is the single accent on the page and the second stop for the eye. Nothing else on the page uses yellow, so it cannot compete with the anchor.

**Filter form.** A native `<details>` wrapping a `<form method="get" action="/" aria-label="Filter tours">`. No client JavaScript on this page at all (D-05); there is no auto-apply on change. Select values come from the URL as `defaultValue`; an invalid value shows "Any".
- Below 64em: the `details` is closed by default (D-01). The `summary` is 44px tall, weight 600, Neel, with the browser's default disclosure marker. It reads "Filters", or "Filters ({n} active)" with the count part in State green. The panel is `--color-surface`, `radius-md`, padding `--space-4`.
- The `details` is rendered with `open` whenever any of the four filters is active, so it stays open after applying (D-01). Proposed: it also opens when `sort` is not the default, so the control shows the current order (Open item 7).
- Inside: five labelled selects in an intrinsic grid, `grid-template-columns: repeat(auto-fill, minmax(min(100%, 12rem), 1fr))`, gap `--space-4`. At 375px that is one column; at 768px it is two or three. No media query is used for it. Then a row with "Show tours" (primary button) and "Clear filters" (link, 44px tall).
- From 64em: Proposed (Open item 6): the summary is hidden and the form content is always visible (`details::details-content { content-visibility: visible }` with the summary `display: none`), so the desktop layout matches the approved mockup: the five selects in a row, then "Show tours" and "Clear filters" at the row end, wrapping to a second row when the width runs out (`display: flex; flex-wrap: wrap; align-items: end; gap: var(--space-4) var(--space-5)`). Inside `@supports not selector(::details-content)` the summary stays visible at all widths so the form is never unreachable.

#### Route map (D-07, R8, U25, ADR 0028)

This section is the confirmed decision under amended D-07 (user-confirmed 2026-11-16), not a proposal.

- **Structure.** An `h2` "Itinerary", then a block with two children: the **map slot** and the **itinerary list**. Below 64em the slot sits above the list. From 64em they sit side by side in the content column, two equal columns (`minmax(0, 1fr) minmax(0, 1fr)`), with the slot top-aligned (`align-self: start`) and the `Itinerary` list at its natural height (day rows at 6rem label plus summary, as built). The itinerary list is rendered once, on the server, in every state: before Leaflet loads, after it loads, and with JavaScript off. It is never hidden, collapsed, replaced or re-rendered, and nothing in `route-map` touches it. It is the always-available text version of the route.
- **Map slot.** A fixed box, `aspect-ratio: 5 / 3`, `--color-surface` background, `radius-md`, padding `--space-3` (the `MapFrame` frame). Its box is the same size whether it holds the static route or the Leaflet map, so nothing moves when the map arrives.
- **Before the map loads and with JavaScript off:** the slot contains `MapFrame` with `animate={false}` (C3): a same-size static route, already drawn, with no animation, Highway yellow line with Neel outline, milestone-shaped day markers. This is the whole of the map with JavaScript off, and the itinerary list stands beside or below it as always.
- **Loading.** `route-map` (client) watches the slot with `IntersectionObserver` (root margin `12rem` so the load starts just before it is visible). On first intersection it imports Leaflet (the import is inside the `next/dynamic` component; Leaflet's JavaScript and CSS are not part of any other route), fetches the India boundary from our own origin (`india-soi.geojson`, ADR 0028), and mounts. Leaflet replaces the static drawing inside the slot only, at the identical box size, and the route then draws once. If any step fails the static route stays and nothing is reported.
- **Map content.** No tile layer and no third-party host. The boundary is drawn as an unfilled outline in `--color-border` at hairline width (`--border-width-hairline`), the slot background is `--color-surface`. The route is two polylines: a Neel outline (weight `8`) under a Highway yellow line (weight `4`), round caps and joins, same as `MapFrame` after C6. Each stop is a milestone-shaped marker (`1.5rem` wide by `1.25rem` high, which is 24 by 20px, `--radius-sm`, Highway yellow fill, `--focus-ring-width` Neel border, Neel numeral, Caption size, weight 600) carrying the day number. Two stops on the same point (Leh on day 1 and day 8 of Ladakh High Passes) are nudged apart by `--space-3` (12px) along the diagonal so both stay visible, as `MapFrame` does after C6. Sizes, nudge and padding are read from the tokens (`getComputedStyle` on the root for `--space-3` and `--space-5`) or set in rem in CSS. The `MapFrame` SVG constants and the Leaflet stroke weights (`8` and `4`) are token-equivalent numbers in JavaScript, each with a comment naming its token, and the C6 unit test fails if `--space-3` or `--space-5` drift from them. Colours come from CSS classes on the SVG paths using tokens, never raw values in JavaScript, so the dark theme works.
- **Extent.** The view is fitted to the route's bounds with `--space-5` (24px) padding, read from the token at runtime, which is the same padding `MapFrame` uses after C6. It is not interactive: no drag, no zoom control, no scroll-wheel or double-click zoom, no keyboard handler, so there is no keyboard trap. The attribution control stays on, with the text from the copy table.
- **Motion.** When the Leaflet map has mounted and is in view, the route line draws once from start to end in `--duration-signature` (1.2 seconds), `ease-out`. It never replays. The static drawing that held the slot never animates. Under `prefers-reduced-motion: reduce` the Leaflet route appears already drawn and no animation runs. This is the only self-playing motion in the phase.
- **Accessibility.** The Leaflet container has `role="img"` and the same accessible name as `MapFrame`: "Route map: {n} stops, days {a} to {b}". The markers are not focusable.
- **Partial data.** Kedarkantha Winter Trek has six days but five stops (day 2, the Juda Ka Talab camp, has no reliable coordinates; `seed/README.md`). The itinerary list shows only the days that have a stop (Day 1, 3, 4, 5, 6) and the description covers day 2. Neither the list nor the map invents a Day 2.
