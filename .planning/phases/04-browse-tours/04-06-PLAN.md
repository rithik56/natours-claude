## Phase Goal

ROADMAP Phase 4 goal, quoted verbatim (not in user-story form; no story is invented): A traveller can find a tour that fits their fitness, dates and budget, and see its route, itinerary, guides, reviews and photo credits. API clients get the same catalogue.

Streaming sections (booking panel, guides list, reviews) follow in plan 04-07 and the Leaflet map in 04-08.

Purpose: a traveller can open any tour and see its route, itinerary, photos and credits; search engines and link previews get correct metadata.
Output: the tour page, `TourRoute`, `TourGallery`, PhotoCredits C7, MapFrame C3, the detail API, ADR 0032.
</objective>

<decisions>
- **No `loading.tsx` on the tour segment or at the app root** (RESEARCH Pitfall 1: verified on Next 16.4.5 that a loading boundary turns a missing slug into HTTP 200). In-page Suspense is used instead (plan 04-07). `/credits` may have one (plan 04-10). Recorded in ADR 0032 as a deviation from R4's "route segments have loading.tsx". Reversibility: reversible.
- **`getBySlug` returns null for a missing slug** (the page calls `notFound()`), and `getById` throws `NOT_FOUND` (the API). plan.md 4.4 says `getBySlug` throws; contracts.md records the difference. Reversibility: reversible.
- **DTO split (RESEARCH Pattern 6):** `toTourDetail` no longer needs populated guides; it returns the detail with `guideIds`, and `toGuides` maps populated guides, skipping missing ones, so the guides list can stream separately. Reversibility: costly (DTO shape used by page and API), settled before any client.
- **`getById` reads uncached** by id, because an id from the URL must never create a cache entry; detail pages use the slug path through the cached catalogue.
- **og:image is the direct `/media/<cover key>` URL on APP_URL** (the original JPEG, under 1 MB), not an optimiser URL (RESEARCH A3 risk avoided). Reversibility: reversible.
- **Author is plain text in captions and credit lists; the licence links** (C7, approved in 04-01).
</decisions>
