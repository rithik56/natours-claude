## Phase Goal

ROADMAP Phase 4 goal, quoted verbatim (not in user-story form; no story is invented): A traveller can find a tour that fits their fitness, dates and budget, and see its route, itinerary, guides, reviews and photo credits. API clients get the same catalogue.

<objective>
The images endpoint (D-12's last item, D-14, B4, S16): `withApi` learns multipart bodies with byte-counted limits, `images.normalize` checks and re-encodes uploads with sharp, and PUT /api/v1/tours/[id]/images replaces the cover and gallery slots by position, each file with its credit.

Purpose: admins and lead guides can add or replace tour photos safely, every photo keeps its credit, and a cover-less tour can be completed and published.
Output: `body.ts`, the `upload` option in `withApi`, `images.ts`, the images route, `replaceImages`, ADR 0038.
</objective>

</decisions>

## Trust Boundaries

| Boundary | Description |

| Staff client → images endpoint | Untrusted file bytes and form parts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-36 | Denial of Service | `readBodyLimited`, `withApi` | high | mitigate | Content-Length checked before reading, bytes counted while streaming, 21 MB images limit and 1 MB JSON limit; access is resolved before any body is read, so anonymous callers cannot make the server buffer (SEC-17); tested |
| T-04-37 | Denial of Service (decompression bomb) | `normalize` | high | mitigate | `limitInputPixels: 40_000_000`, `pages: 1`, `sharp.concurrency(1)`, 5 MB per file; the 16,000 × 16,000 PNG test is refused with 413 |
| T-04-38 | Spoofing (MIME) | uploaded files | high | mitigate | Magic bytes decide the type, the declared type is ignored; sharp re-encodes to WebP, stripping metadata; `X-Content-Type-Options: nosniff` is global |
| T-04-39 | Elevation of Privilege / abuse | images route | medium | mitigate | `access: { roles: ['lead-guide', 'admin'] }`, Origin check on PUT, per-user limit of 20 per hour (SEC-05) |
| T-04-40 | Tampering (path) | stored keys | medium | mitigate | Keys are generated server-side as `tours/<uuid>.webp`; no client-supplied file name is used |
| T-04-SC | Tampering | npm install (sharp@0.35.5) | high | mitigate | Legitimacy audit OK (VERIFIED, ~166M/wk, already in the lockfile through Next); exact version pinned; reason in the commit body |
