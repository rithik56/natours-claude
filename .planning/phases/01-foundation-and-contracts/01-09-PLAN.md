- Primary noun: the session subject, the User `_id` carried in the JWT `sub` and verified with the single pinned algorithm HS256.
- Decision: no-change. "Another algorithm" names a rejection case, not a second supported algorithm, secret or identity source, so nothing is being generalised and there is nothing to promote.

Add the following to `src/server/session.ts`.

`getCurrentUser` is wrapped in React `cache()`, and its signature is `(cookieSource?: CookieReader) => Promise<SelfUser | null>`. Route Handlers pass `request.cookies`; pages and actions pass nothing. Each call:
- runs `getSession`;
- calls `findActiveById(session.userId)`;
- returns null when there is no session, no active record, or `session.iat < Math.floor(passwordChangedAt.getTime() / 1000)` (equality is accepted, SEC-18);
- otherwise returns `toSelf(record)`.

The role always comes from this database read (Key Decision 11). Outside React Server rendering, `cache()` does not deduplicate, so tests prove the per-call read. Don't write a "runs once per request" test (RESEARCH Pattern 3).

`requireUser(options?: { next?: string }): Promise<SelfUser>`:
- with no user and `options.next` given, it calls `redirect('/login?next=' + encodeURIComponent(safeNext(options.next)))` from `next/navigation`;
- with no user and no `next`, it throws `new AppError('UNAUTHENTICATED')`.

`requireRole(roles: readonly Role[], options?: { next?: string })` calls `requireUser`, then throws `new AppError('FORBIDDEN')` unless `roles` includes the user's role. There is no role hierarchy: lists are explicit. Both helpers always go through `getCurrentUser()` (S6 amended).

`test/helpers/request-context.ts` holds a module-level mutable store:
- a cookie store with `get`, `getAll`, `has`, `set` and `delete`, enough for the session code and later Server Actions;
- a `Headers` object holding `x-request-id`;
- `resetRequestContext()`, which clears the cookies and sets a fresh UUID request ID.

`test/setup.ts` adds `vi.mock('next/headers', …)`, returning async `cookies()` and `headers()` from that store, and a `beforeEach(resetRequestContext)`.

`test/helpers/mock-session.ts` exports `mockSession(user: { _id: unknown } | { id: string } | null): Promise<void>`. It sets the cookie to `await signSession(id)`, or deletes it for null.

ADR 0015 (Key Decision 11, S14 amended, SEC-02, SEC-18) records:
