# Phase 01 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser to the proxy (page requests) | `src/proxy.ts` runs on page requests only. It sets a per-request CSP nonce and replaces `x-request-id`. | Page URLs, cookies, client-supplied headers (`x-request-id`) |
| Browser or API client to Route Handlers | Every request goes through `withApi`: Origin check on writes, required `access`, params, query and body validation, then the rate limit. | Session cookie, Origin header, JSON bodies, query strings: all untrusted |
| Browser form POST to Server Actions | Any exported action is reachable by a direct POST. `action()` checks access, parses FormData with Zod and returns an `ActionState`. Next.js checks the Origin. | Attacker-controlled FormData; serialised `ActionState` going back |
| Session token to the server | The cookie token is attacker-controllable input. `getSession` verifies it and `getCurrentUser` re-reads the user and role from MongoDB on every call. | HS256 JWT (`sub`, `iat`, `exp`), `SESSION_SECRET` |
| Server to MongoDB | Models, hooks and the connection. Credentials and password hashes cross here; the database may be unreachable. | Connection string, user records, bcrypt hashes, prices and bookings |
| Server to browser and log sink | Data leaves only through DTO mappers, the error envelope, `ActionState` and pino logs. | User and tour data, error messages, request IDs, log lines |
| Environment to server, and repository to public | Deploy-time environment becomes runtime config. `.env.example` and the docs are committed to a public repository. | `APP_ENV`, `APP_URL`, `SESSION_SECRET`, `MONGODB_URI`, documentation text |
| Server to outside services | Mail, queue, Stripe, storage and rate limiting are reached only through adapters. `APP_ENV` decides fakes or the refusal to run. | Email jobs, checkout sessions, webhook signatures |
| CI and GitHub | npm packages and GitHub Actions run with repository access; Lighthouse and Chrome run against the built app; workflow artifacts are downloadable from a public repository. | Third-party code, lockfile, CI artifacts |
| Developer machine to public GitHub | `git push` publishes every commit. The working tree holds the user's own uncommitted files. | Commits, `.claude/settings.json`, `.planning` edits |
