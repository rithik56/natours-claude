<objective>
Build the Route Handler pipeline. Every API route uses `withApi`, which:
- mints or reuses the request ID;
- checks the Origin on writes (S9) and applies CORS only for allowlisted origins (S10);
- refuses any route without an access declaration and checks the declared access through `getCurrentUser()` (S1, SEC-15);
- validates params, query and body with Zod;
- applies an optional rate limit;
- maps every error to the §4.1 envelope with the request ID, logged with the same ID (B9, D7).

Move `/healthz` and `/readyz` onto it, and add `callRoute` with the Route Handler example tests.

Purpose: Phase 1 success criterion 3's pipeline clauses and success criterion 5's test helper. Every Route Handler in Phases 4 to 6 is a `withApi` call.
Output: `error-mapper.ts`, `api/{responses,parse-query,origin,with-api}.ts`, `access.ts`, the routes, `callRoute`, tests, and ADR 0017.
</objective>

`src/server/error-mapper.ts` (server-only) exports `toAppError(err: unknown): AppError`. The order is important (B9 ordering):
1. `isAppError`: return it as is.
2. `err instanceof z.ZodError`: VALIDATION_ERROR with `issuesToDetails`.
3. `isDbUnavailableError`: SERVICE_UNAVAILABLE.
4. `name === 'CastError'`: VALIDATION_ERROR with one detail, the path and `messages.validation.invalidId`.
5. `name === 'ValidationError'` (Mongoose): VALIDATION_ERROR, with one detail per key of `err.errors` using `messages.validation.invalidValue`.

8. `errors.JOSEError`: UNAUTHENTICATED.
9. `type === 'StripeSignatureVerificationError'`: VALIDATION_ERROR.

`src/server/access.ts` (server-only) exports:
- `type Access = 'public' | 'auth' | 'owner' | { roles: readonly Role[] }` (SEC-15);
- `resolveAccess(access: Access | undefined, cookieSource?): Promise<SelfUser | null>`.

`resolveAccess` throws `AppError('FORBIDDEN')` when `access` is undefined or not one of the allowed shapes. It returns null for public without reading the session, calls `requireUser()` for auth and owner, and `requireRole(access.roles)` for roles, both with the cookie source passed through to `getCurrentUser`. Owner means "authenticated, ownership enforced in the service". It exists so the Phase 6 access matrix can classify routes.

`src/server/api/origin.ts` (server-only) exports:
- `isAllowedOrigin(origin: string | null): boolean`: null, APP_URL's origin, or an entry in `corsOrigins` (SEC-26);
- `corsHeaders(origin: string | null): Record<string, string>`: `Access-Control-Allow-Origin` and `Vary: Origin` only for `corsOrigins` entries, and never credentials (S10);
- `handlePreflight(request: NextRequest): Response`: 204, plus `Access-Control-Allow-Methods` (GET, POST, PUT, PATCH, DELETE), `Access-Control-Allow-Headers` (content-type) and `Access-Control-Max-Age` 600, when the origin is allowlisted. API route files in later phases export it as `OPTIONS`.

`src/server/api/with-api.ts` (server-only) exports `withApi(handler, options)`. It returns `(request: NextRequest, context: { params: Promise<Record<string, string | string[]>> }) => Promise<Response>`. `options` has a required `access`, plus optional `body`, `query` and `params` Zod schemas and `rateLimit: { rule: RateLimitRule; key: (input: { request: NextRequest; body: unknown }) => string }`. The pipeline order is fixed:
1. Request ID: reuse an incoming `x-request-id` only if it is a UUID, otherwise `crypto.randomUUID()`. Create `log = requestLogger(id)`.
2. Origin check for POST, PUT, PATCH and DELETE: FORBIDDEN unless `isAllowedOrigin` (S9). The Stripe webhook in Phase 6 is not wrapped this way.
3. `resolveAccess(options.access, request.cookies)`.
4. Params, then query (from `request.nextUrl.searchParams`, strict), then body. The body must have a JSON content type (else UNSUPPORTED_MEDIA_TYPE); a JSON parse failure is VALIDATION_ERROR with `messages.validation.invalidJson`. Multipart arrives in Phase 4.
5. The rate limit through `getDeps().rateLimiter.consume(key, rule)`: RATE_LIMITED with `Retry-After`.
6. `handler({ request, params, query, body, user, requestId, log })`.

On any throw:
- call `unstable_rethrow(err)` from `next/navigation` first;
- then `toAppError`;
- log it with the request ID: warn below 500, and error with the original error and stack at 500 or above, never in the body;
- respond with `errorResponse`.

Every response gets `x-request-id` and `corsHeaders(origin)`.
