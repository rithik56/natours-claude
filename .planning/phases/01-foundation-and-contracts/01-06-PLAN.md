`src/proxy.ts` exports `function proxy(request: NextRequest)` and `config`. For each request it creates:
- `nonce`, as `Buffer.from(crypto.randomUUID()).toString('base64')`;
- `requestId`, as `crypto.randomUUID()`, which always overwrites any incoming value.

It builds the policy with an unexported function. The directives, in this fixed order (RESEARCH Pattern 6):
- `default-src 'self'`;
- `script-src 'self' 'nonce-N' 'strict-dynamic'`, plus `'unsafe-eval'` only when `process.env.NODE_ENV` is development;
- `style-src-elem 'self' 'nonce-N'`;
- `style-src-attr 'unsafe-inline'`;
- `img-src 'self' blob: data:`;
- `font-src 'self'`;
- `connect-src 'self'`;
- `form-action 'self' https://checkout.stripe.com` (SEC-14: Phase 6's no-JS redirect to Stripe);
- `frame-ancestors 'none'`;
- `base-uri 'self'`;
- `object-src 'none'`;
- `upgrade-insecure-requests`, only when `process.env.APP_ENV` is staging or production.

Map-tile and storage hosts are added by Phase 4 after the D14 ADR.

Clone the request headers and set `x-nonce`, `x-request-id` and `content-security-policy` on them. Return `NextResponse.next({ request: { headers } })`, and set `content-security-policy` and `x-request-id` on the response too.

`config.matcher` is the single-object form from RESEARCH Pattern 6:
- source `/((?!api|webhooks|healthz|readyz|_next/static|_next/image|favicon.ico).*)`;
- `missing` entries for the `next-router-prefetch` header and for `purpose: prefetch`.

The proxy does no auth and no early login redirect in Phase 1: no protected page exists, and Phase 5 adds that convenience redirect.

`next.config.ts`:
- `poweredByHeader: false`.
- `async headers()` returning source `/:path*` with:
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains`;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: strict-origin-when-cross-origin`;
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()`;
  - `X-Frame-Options: DENY`.
- Leave Cache Components off and don't set `serverActions.allowedOrigins` (S9). `serverActions.bodySizeLimit` is left for Phase 4 (S16).

ADR 0011 (S11 requires an ADR for any inline-style allowance; ARC-20, DES-11) records why `style-src-attr 'unsafe-inline'` is allowed:
- `next/image` always writes inline style attributes, and a nonce cannot cover attributes;
- `style-src-elem` stays nonce-only, and scripts never get `'unsafe-inline'`;
- the residual risk is CSS injection through style attributes, with no script execution.
